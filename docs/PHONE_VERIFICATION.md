# Physical-phone delivery verification

Use a Google Play services phone. Install the debug APK over the previous build to exercise the database upgrade. Keep a backup of anything important before uninstalling; Ariciu deliberately does not use cloud backup.

1. **Upgrade and setup:** Confirm existing reminders survive. Open Delivery setup. Decline each permission once: managing reminders should still work and delivery must show the missing requirement. Then allow precise foreground location, background location (Allow all the time), and notifications separately. Enable device location. Confirm each active reminder eventually reports registered monitoring.
2. **Arrival and departure:** Use a real nearby area with a 200–500m radius. Create separate ENTER and EXIT reminders. With the UI closed and phone locked, cross clearly outside/inside the radius and wait several minutes. ENTER should alert on arrival; EXIT should alert on departure. Registering while already inside should not immediately alert. Test while standing still as well as walking; do not test while driving yourself.
3. **Once and repeated visits:** Stay inside after an ENTER alert: no duplicate occurrence should appear. A Once reminder should remain triggered across additional visits until Next time. An Every visit reminder should alert again only after leaving and returning. For EXIT, return inside before leaving again. Boundary jitter and missed platform crossings remain possible.
4. **Actions and dismissal:** Test Done, Next time, and swiping with the UI closed. Done should show Completed and remove monitoring. Next time/swipe should dismiss the occurrence and wait for another distinct visit. Tap a notification: the corresponding reminder should be visible and highlighted. Test an old action after a newer occurrence and after editing: it must not complete the newer occurrence.
5. **Editing and deletion:** Change a title and area after registration. The old area must not trigger the edited reminder. Editing a triggered Once reminder must not rearm it; editing a completed reminder must not undo Done. Delete an active reminder and verify its old area no longer alerts. If registration fails, use Retry monitoring after restoring the cause.
6. **Recovery:** Reboot, unlock, and allow Android time to execute recovery without opening Ariciu. Repeat a boundary crossing. Test an app update over the existing installation. Kill the background process (not Force stop) and repeat actions/crossings. Force stop is an Android restriction: reopen Ariciu before expecting delivery to resume.
7. **Settings changes:** Revoke precise/background/notification permissions; disable Location; disable the Normal reminders channel. Return to Ariciu and confirm accurate status and working shortcuts. Restore access and Retry. Check silent channel settings and Do Not Disturb: Ariciu must respect them and does not guarantee heads-up alerts.
8. **Restrictions and connectivity:** Test battery saver, restricted app battery settings, weak/no network-assisted positioning, and Wi-Fi scanning disabled. Record Android version, device model, timestamps, radius, permissions, and observed delays. Geofencing and WorkManager may be delayed or suppressed; local storage does not guarantee entirely disconnected positioning.

Automated tests exercise lifecycle logic, database migration, registration planning with a fake backend, and actual Android notification/action intents with injected crossing commands. They do not establish real Play services boundary detection, reboot delivery, OEM battery behavior, sound, or heads-up presentation. No physical-device verification has been performed for this batch.
